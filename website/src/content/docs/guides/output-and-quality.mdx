## Output formats

Every render resolves to a structured `MarkerResult`. The table describes
`result.uri`; inspect `result.format`, `result.mimeType`, `result.output`, and
`result.metadata` instead of inferring them from a filename.

| `saveFormat` | iOS `result.uri` | Android `result.uri` | Web `result.uri` | Best for |
| --- | --- | --- | --- | --- |
| `ImageFormat.jpg` | Cache-file path | Cache-file path | JPEG data URL | Photos and smaller files |
| `ImageFormat.png` | Cache-file path | Cache-file path | PNG data URL | Transparency, QR codes, icons, and sharp edges |
| `ImageFormat.webp` | Explicitly rejected | Cache-file path | WebP data URL | Smaller modern output where the platform is known |
| `ImageFormat.base64` | PNG data URL | PNG data URL | PNG data URL | In-memory transfer when you explicitly need base64 |

JPEG is the compatibility default. Set the format explicitly when output behavior matters.

```ts
const result = await Marker.markImage({
  backgroundImage: { src: require('./background.png') },
  watermarkImages: [
    {
      src: require('./logo.png'),
      trimTransparentPadding: true,
    },
  ],
  filename: 'marked-photo',
  saveFormat: ImageFormat.png,
});

await shareOrDownload(result.uri);
```

## Quality

`quality` accepts an integer from `0–100`, where `100` is the highest quality. It has the most visible effect on JPEG because PNG output is lossless. Browser and native JPEG encoders can produce different bytes and file sizes for the same value.

For QR codes, barcodes, pixel art, and line-art logos, choose PNG. JPEG compression can soften hard edges even at high quality.

## JPEG and transparency

JPEG has no alpha channel. When transparent pixels are saved as JPEG, `matteColor` selects the solid color placed behind them. The default is white.

```ts
saveFormat: ImageFormat.jpg,
quality: 92,
matteColor: '#FFFFFF',
```

<Aside type="tip">
  Use PNG when the final image itself must remain transparent.
</Aside>

## Rotated backgrounds

The default `RotationCanvasMode.expand` grows the output canvas so the full rotated image remains visible. Choose `crop` to keep the original canvas size and clip content outside it.

```ts
backgroundImage: {
  src: require('./background.jpg'),
  rotate: 30,
},
rotationCanvasMode: RotationCanvasMode.crop,
```

## Filenames and storage

On native targets, supported file output lives in the app's cache directory. `filename` must be a safe basename, not a directory path. A supplied `.jpg`, `.jpeg`, `.png`, or `.webp` suffix is normalized to match `saveFormat`.

Cache output does not automatically appear in the photo library. Pass the returned path to your preferred media-library or file-system package when you need a permanent copy.

Web does not write a cache file: `result.uri` is a data URL and Web does not use `filename`. Set an anchor's `download` attribute or use your own browser file workflow when saving it.

Data URLs keep more image data in JavaScript memory. This applies to every Web output and native base64 output, so avoid unnecessarily large source images.

## Orientation and metadata

Core 2 applies source orientation to pixels before composition and reports
`result.metadata.orientation === 'normalized'`. It deliberately strips copied
EXIF, GPS, and other source metadata from newly encoded output, reported as
`result.metadata.policy === 'strip'`. This avoids stale orientation and
accidental location leakage. Use an explicit Content Credentials adapter when
you need signed provenance.
