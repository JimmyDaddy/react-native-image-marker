# RFC 0001：v1.9 数据驱动水印模板

- 状态：Accepted
- 目标版本：v1.9
- 适用平台：iOS、Android、Web

## 背景

v1.8 引入了可复用的 recipe、受控批处理与 Web Blob 输出，但每次执行只能替换底图和输出文件名。活动摄影、电商图、证件照和企业素材等批量场景还需要为每张图片注入姓名、编号、日期等不同内容。

本 RFC 在 recipe 层增加可序列化变量、条件图层与版本化定义。变量在 JavaScript 层解析成现有 `MarkOptions`，因此不修改 native bridge，也不增加三个渲染器之间的行为差异。

## 目标

1. 同一个 recipe 可以为每个输入解析不同的文字。
2. 文本和条件使用确定、可序列化的声明式语法。
3. recipe 可以通过 JSON 保存并重新创建。
4. 单张执行与批处理具有一致的变量校验行为。
5. 保持 v1.8 recipe 调用完全兼容。

## 非目标

- 不支持在模板里执行 JavaScript 表达式。
- 不支持嵌套对象取值、日期格式化或算术运算。
- 不允许变量修改位置、字体、输出质量等任意配置。
- 不改变 native 渲染器或 bridge 参数。

## 公共 API

### Recipe 定义

```ts
type WatermarkRecipeVariable = string | number | boolean;

interface WatermarkRecipeCondition {
  variable: string;
  equals: WatermarkRecipeVariable;
}

interface WatermarkRecipeOptions {
  schemaVersion?: 1;
  watermarks: WatermarkRecipeLayer[];
  // 其余输出选项保持不变
}

interface WatermarkRecipeInput {
  backgroundImage: ImageOptions;
  filename?: string;
  variables?: Readonly<Record<string, WatermarkRecipeVariable>>;
}
```

每个 recipe 图层可以增加：

```ts
interface WatermarkRecipeLayerOptions {
  visibleWhen?: WatermarkRecipeCondition;
}
```

`visibleWhen` 只属于 recipe 定义，在渲染前会被移除，不会传入 native bridge。

### 文本模板

文字图层的 `text` 支持 `{{variable}}`：

```ts
const recipe = Marker.createRecipe({
  schemaVersion: 1,
  watermarks: [
    {
      type: 'text',
      text: '{{name}} · #{{number}}',
      position: { position: Position.bottomLeft },
    },
  ],
});

await recipe.apply({
  backgroundImage: { src: photo },
  variables: { name: 'Jimmy', number: 18 },
});
```

变量名必须匹配 `[A-Za-z_][A-Za-z0-9_.-]*`。反斜杠可以转义模板开头：`\{{name}}` 输出字面量 `{{name}}`。

### 内置变量

- `filename`：当前输入的输出文件名。没有文件名时视为缺失。
- `index`：当前输入在批处理中的零基索引；单张 `apply()` 时为 `0`。

输入的 `variables` 不允许覆盖 `filename` 与 `index`。

### Recipe 版本与序列化

```ts
interface WatermarkRecipe<Result = string> {
  readonly schemaVersion: 1;
  toJSON(): WatermarkRecipeDefinition;
  apply(input: WatermarkRecipeInput): Promise<Result>;
  applyMany(...): Promise<WatermarkBatchResult<Result>[]>;
}
```

`JSON.stringify(recipe)` 会调用 `toJSON()`。返回定义是深拷贝，修改它不会改变已经创建的 recipe。

## 校验和错误语义

1. `schemaVersion` 缺省时按 `1` 处理；其他值立即拒绝。
2. 变量值只允许字符串、有限数字和布尔值。
3. 模板或条件引用缺失变量时抛出包含变量名的错误。
4. `visibleWhen` 使用类型和值都相同的严格比较。
5. `applyMany()` 中的模板错误只将对应项标记为 `rejected`，其他输入继续执行。
6. recipe 创建时仍执行静态渲染参数校验；含模板的文字会用安全占位内容通过现有校验。

## 兼容性

- 没有模板、条件或变量的 v1.8 recipe 行为不变。
- recipe 解析后仍调用现有 `Marker.mark()`，native 与 Web 输出契约不变。
- 新字段只出现在 TypeScript/JavaScript recipe 层，不需要重新安装 native development build。

## 测试计划

- 模板：字符串、数字、布尔值、多变量、重复变量和转义。
- 错误：非法变量、缺失变量、保留变量、非有限数字和未知 schema。
- 条件：文字/图片图层显示与隐藏、严格类型比较。
- 批处理：内置 `index`、单项拒绝、顺序、进度与取消不回归。
- 序列化：深拷贝、JSON round-trip、重新创建结果一致。
- Playground：多输入个性化变量示例与生成代码。

## 发布策略

与 RFC 0002 的跨平台图层混合模式合并为一次 v1.9.0 minor release。若实现过程中需要表达式、嵌套路径或任意覆盖能力，必须另起 RFC，不在本版本扩张语法。
