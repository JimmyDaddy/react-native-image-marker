# 开发文档目录

本目录包含项目开发过程中产生的技术文档，用于记录问题修复、优化方案、架构变更等开发相关信息。

## 文档分类

### 问题修复文档
记录开发过程中遇到的问题及其解决方案：
- `KOTLIN_VERSION_FIX.md`: Kotlin 版本兼容性问题修复
- `ENUM_KEY_FIX_SUMMARY.md`: 枚举键值问题修复总结

### 优化文档
记录性能优化、流程优化等改进措施：
- `CI_OPTIMIZATION.md`: CI 流水线优化说明
- `ANDROID_API_TEST_REMOVAL.md`: Android API Level 测试移除说明

### 架构文档
记录架构设计和变更：
- `ARCHITECTURE.md`: 项目架构说明
- `WORKFLOW_MERGE.md`: 工作流合并说明

## 文档规范

### 命名规范
- 使用大写字母和下划线命名，如 `FEATURE_NAME.md`
- 文件名应清晰表达文档内容
- 避免使用缩写，除非是广为人知的术语

### 内容规范
每个文档应包含以下部分（根据实际情况调整）：

1. **标题和摘要**：简要说明文档主题
2. **背景/问题描述**：为什么需要这个变更
3. **解决方案/实现方式**：具体的技术方案
4. **影响范围**：变更影响的模块和功能
5. **相关资源**：相关文件、PR、Issue 链接

### 语言规范
- 使用中文撰写，技术术语保留英文
- 代码示例使用英文注释
- 保持简洁清晰，避免冗余

## 与用户文档的区别

### 用户文档（项目根目录）
面向库的使用者，包括：
- `README.md`: 项目介绍、安装、使用指南
- `CONTRIBUTING.md`: 贡献指南
- `CHANGELOG.md`: 版本变更日志

### 开发文档（docs/dev/）
面向项目开发者和维护者，包括：
- 问题修复记录
- 优化方案说明
- 架构设计文档
- 开发过程中的技术决策

## 文档维护

- 每次重要的问题修复、优化或架构变更都应创建对应文档
- 文档应及时更新，保持与代码同步
- 过时的文档应标注或归档
- 定期审查文档，确保准确性和完整性
